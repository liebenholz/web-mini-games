# 보물 찾기(treasure) 명세서 v0.1

- 작성일: 2026-11-28
- 상태: 결정 반영 (2026-11-28). 화면 시안 확인 뒤 구현한다
- 화면 이름: **보물 찾기** / 코드·주소 이름: **`treasure`** (`/treasure`, `/treasure/r/<코드>`, 방 종류 `treasure`)
- 공통 구조(방 코드, 대기실, 재접속, 봇 대체, 추방, 이탈 기록, 리매치)는 ADR 0003 공통 엔진과 `liars-dice.md`를 따른다. 이 문서는 보물 찾기에서 다른 점만 적는다
- **파티 게임**이다. 카테고리, 결과 화면(당첨/통과), 기록 방식은 `updown-bomb.md` 9장(파티 게임 공통)을 따른다
- 출처: 누구나 아는 "보물 찾기" 놀이 규칙. 사내 동료의 WHO? 페이지에서 후보로 골랐지만 코드, 문구, 그림은 가져오지 않는다
- **업다운·풍선과 다른 점:** 차례제가 아니라 **모두 동시에** 고른다 (숫자야구의 동시 진행 구조)

## 1. 개요

판 위 한 칸에 보물이 숨어 있다. 모두가 몰래 칸을 하나씩 고르고, 모두 고르면 보물을 공개한다. **보물에서 가장 먼 칸을 고른 한 명**이 당첨된다.

| 항목 | v1 결정 |
| --- | --- |
| 인원 | 2~10명 (봇 포함) + 관전. **기본 6명** (2026-11-28) |
| 판 | 9×9 칸. 칸을 하나 눌러 고른다 |
| 진행 | 모두 동시에 한 칸씩 고른다. 서로의 선택은 모두 고를 때까지 보이지 않는다 |
| 거리 | 칸 중심 사이의 직선거리 (제곱으로 비교한다, 정수 계산) |
| 당첨 | **보물에서 가장 먼 사람 1명.** 같은 거리가 둘 이상이면 동점자끼리 새 보물로 재대결 (BH-07) |
| 선택 시간 | 15초 (방 옵션, 모두에게 같은 마감 하나) |
| 시간 초과 | 못 고른 사람은 서버가 무작위 칸을 대신 고른다 (BH-12) |
| 목표 플레이 시간 | 1~2분 |
| 베팅 / 재화 | 없음 |

## 2. 규칙

| ID | 규칙 | 상세 |
| --- | --- | --- |
| BH-01 | 판과 좌표 | 9×9 칸. 칸 번호는 열 A~I, 행 1~9. 보물은 판이 시작될 때 서버가 `crypto.randomInt`로 한 칸을 고른다. 판이 끝날 때까지 바뀌지 않는다 |
| BH-02 | 선택 | 선택 단계에서 각자 칸 하나를 고른다. 마감 전에는 **바꿀 수 있고**, 마감되거나 모두 확정하면 끝난다. 같은 칸을 여럿이 골라도 된다 |
| BH-03 | 확정 | 사람은 "확정"을 눌러 선택을 잠근다. 잠그면 바꿀 수 없다. 모두 확정하면 마감을 기다리지 않고 바로 공개한다 |
| BH-04 | 공개 | 마감되거나 모두 확정하면 보물 위치와 모든 선택을 한꺼번에 공개한다 |
| BH-05 | 거리 | 거리의 제곱 = (열 차이)² + (행 차이)². 제곱이 큰 쪽이 더 멀다 |
| BH-06 | 당첨 | 거리의 제곱이 가장 큰 사람이 하나면 그 사람이 당첨되고 판이 끝난다 |
| BH-07 | 동점 | 가장 먼 거리가 같은 사람이 둘 이상이면 **그 사람들만** 남아 새 보물로 다시 고른다 (재대결). 한 명이 가려질 때까지 반복한다. 재대결 단계의 선택 시간은 처음과 같다. 나머지 사람은 통과이고 관전으로 지켜본다. 재대결은 최대 5번이고 그래도 같으면 남은 동점자 중 서버가 무작위로 한 명을 당첨으로 정한다 (`tieBreak`) |
| BH-08 | 리매치 | 같은 방 대기실로. 새 판에서는 보물을 다시 뽑는다 |

### 예시 (4명, 보물 E5)

| 이름 | 고른 칸 | 거리² | |
| --- | --- | --- | --- |
| A | E5 | 0 | |
| B | C4 | 4 + 1 = 5 | |
| C | A9 | 16 + 16 = 32 | **가장 멀다 → C 당첨** |
| D | I1 | 16 + 16 = 32 | 동점 → C와 D만 새 보물로 재대결 |

## 3. 진행

```
WAITING → STARTING(3초) → PICKING ⟲(재대결) → REVEAL(3초) → GAME_OVER → (리매치) → WAITING
```

- STARTING: 좌석 확정, 보물 뽑기
- PICKING: 선택 단계. 마감 하나(15초). 모두 확정하거나 마감되면 → REVEAL
- REVEAL: 보물과 모든 선택, 거리, 가장 먼 사람을 공개하는 연출 (3초). 한 명이면 → GAME_OVER, 동점이면 → 재대결 PICKING (남은 사람만)
- GAME_OVER: 당첨자, 보물 위치, 거리표 공개. 리매치 가능

## 5. 정보 은닉

| ID | 규칙 |
| --- | --- |
| BH-20 | 보물 위치는 서버 메모리에만 둔다. 공유 상태와 REVEAL 전의 어떤 메시지에도 넣지 않는다 (원칙 4) |
| BH-21 | **다른 사람의 선택은 REVEAL 전에 보내지 않는다.** 본인에게만 자기 선택(`your_pick`)을 보낸다. 공유 상태에는 "확정했는지"(`locked`)만 넣는다 |
| BH-22 | 봇 판단에도 보물 위치를 주지 않는다 |
| BH-23 | REVEAL 때 모든 선택과 보물을 공개하고 `reveal`로 한 번에 보낸다 |

## 6. 메시지 (공통과 다른 것)

### 클라이언트 → 서버

| 이벤트 | 페이로드 | 거부 |
| --- | --- | --- |
| `pick` | `x`, `y` (0~8), `roundId` | 선택 단계가 아님(`INVALID_STATE`), 이미 확정함(`INVALID_STATE`), 판 밖·정수 아님(`INVALID_MOVE`), 지난 `roundId`(`STALE_TURN`), 재대결에서 빠진 사람(`NOT_YOUR_TURN`) |
| `lock_pick` | `roundId` | 고른 칸이 없음(`INVALID_MOVE`), 이미 확정함·단계 아님(`INVALID_STATE`), `STALE_TURN`, `NOT_YOUR_TURN` |

`roundId`는 선택 단계(처음, 재대결)마다 새로 발급한다.

### 서버 → 클라이언트

| 이벤트 | 대상 | 내용 |
| --- | --- | --- |
| `round_start` | 전체 | `roundId`, 참가자 playerId 목록, 마감 시각(서버 시간), 재대결 횟수 |
| `your_pick` | 본인만 | 서버가 받아 둔 내 선택 (x, y), 확정 여부. 재접속하면 다시 보낸다 |
| `pick_locked` | 전체 | playerId (확정했다는 것만, 칸은 없음) |
| `reveal` | 전체 | 보물 (x, y), 각자의 선택 (x, y)와 거리², `isAuto`, 가장 먼 사람(들), 재대결 여부 |
| `game_over` | 전체 | `loserId`, 보물, `tieBreak`(최대 재대결 뒤 무작위로 정했는지) |
| 공통 | | `welcome`, `player_replaced`, `error` |

공유 상태: `phase, roomCode, hostId, options, players(공통 필드 + seat, locked, inRound, autopilot, replaced), roundId, round(재대결 횟수), deadline, phaseEndsAt, history[](각 단계의 보물과 선택, REVEAL 뒤에만 채움), loserId, tieBreak`. **보물과 선택 칸은 REVEAL 전에는 상태에 넣지 않는다.**

## 7. 시간, 퇴장, 재접속, 봇

| ID | 영역 | 규칙 |
| --- | --- | --- |
| BH-10 | 시간 | 마감 시각은 서버 기준. 선택 단계에 마감 하나 (모두 같다) |
| BH-11 | 퇴장·끊김 | 공통: 끊겨도 시간은 흐르고, 60초가 지나거나 스스로 나가면 봇이 이어받는다. 이미 확정했다면 그 선택은 그대로 둔다 |
| BH-12 | 시간 초과 | 마감까지 확정하지 않은 사람은, 칸을 골라 뒀다면 **고른 칸을 그대로 확정**하고, 못 골랐다면 서버가 **무작위 칸**을 대신 고른다 (`isAuto`는 무작위로 정한 경우만). 못 골라서 대신 고른 일이 2번 연속이면 봇이 대신 진행하고(autopilot), 직접 고르면 돌려받는다 |
| BH-13 | 봇 | 서버 안에서 돈다. 선택 단계 시작 1~3초 뒤 무작위 칸을 고르고 바로 확정한다. 보물을 모르므로 어떤 칸이든 가장 멀 확률이 같다 |
| BH-14 | 봇의 시간 | 봇이 맡은 자리는 시간 초과가 없다 |

무작위 칸으로 정하는 이유: 칸을 고정하면(예: 가운데) 일부러 시간을 넘기는 쪽이 유리해진다.

## 10. 기록 (DB)

판 요약(ADR 0002, `games.summary`): 인원, 재대결 횟수(`rounds`), 마지막 단계의 보물과 거리², 확정을 누른 사람 수와 시간 초과로 대신 고른 수(`autoMoveCount`), 무작위로 정했는지(`tieBreak`), 봇 여부. 순위는 파티 게임 공통(당첨자 2위, 나머지 1위). `/stats` 게임별 지표: 평균 재대결 횟수, 시간 초과로 대신 고른 비율, 동점이 나온 판 비율.
