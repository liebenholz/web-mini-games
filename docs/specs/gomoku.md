# 오목(gomoku) 명세서 v0.1 (초안)

- 작성일: 2026-11-24
- 상태: 결정 반영 (2026-11-24). 승인되면 Phase 2 M2 구현을 시작한다
- 화면 이름: **오목** / 코드·주소 이름: **`gomoku`** (`/gomoku`, `/gomoku/r/<코드>`, 방 종류 `gomoku`)
- 공통 구조(방 코드, 대기실, 재접속, 봇, 추방)는 거짓말쟁이 주사위 명세(`liars-dice.md`)와 ADR 0002를 따른다. 이 문서는 오목에서 다른 점만 적는다.

## 1. 개요

2명이 15×15 판의 교차점에 번갈아 돌을 두고, 가로·세로·대각선으로 다섯 개를 먼저 잇는 사람이 이긴다. 흑이 먼저 둔다. 흑에게만 적용하는 금수(둘 수 없는 자리) 규칙을 방장이 고른다.

| 항목 | v1 결정 |
| --- | --- |
| 인원 | 2명 (빈자리는 봇) + 관전 |
| 판 | 15×15 교차점 |
| 선 | **항상 흑**. 누가 흑을 할지는 방장이 정한다 (방 옵션) |
| 금수 | 흑에게만. 3-3, 4-4, 장목을 각각 방장이 켜고 끈다. 기본은 모두 켬(렌주) |
| 턴 시간 초과 | **시간패** (연결이 끊긴 동안에도 같다) |
| 게임 중 퇴장 | 봇이 이어서 둔다. 상대에게 알린다 |
| 무르기 | 없음 |
| 베팅 / 재화 | 없음 |

## 2. 규칙

| ID | 규칙 | 상세 |
| --- | --- | --- |
| G-01 | 판과 좌표 | 15×15 교차점. 좌표는 열 A~O(왼쪽→오른쪽), 행 1~15(아래→위). 예: 가운데는 H8 |
| G-02 | 색과 선 | 흑과 백 한 명씩. 흑이 먼저 둔다. 흑을 맡는 사람은 방 옵션(4장)으로 정한다 |
| G-03 | 착수 | 자기 차례에 빈 교차점 하나에 돌을 둔다. 둔 돌은 옮기거나 없애지 않는다 |
| G-04 | 승리: 오목 | 같은 색 돌이 가로·세로·대각선으로 연속 5개가 되면 그 수를 둔 사람이 이긴다 |
| G-05 | 장목(6개 이상) | **백**: 6개 이상도 승리. **흑**: "장목 금지"가 꺼져 있으면 승리, 켜져 있으면 금수(G-07) |
| G-06 | 정확히 5개 우선 | 흑이 둔 수가 정확히 5개를 만들면, 같은 수가 3-3이나 4-4에 해당해도 금수가 아니라 승리다 |
| G-07 | 금수 | 흑이 켜진 금수에 해당하는 자리에 두려 하면 거부한다 (`FORBIDDEN_MOVE`, 상태 변화 없음). 백에게는 금수가 없다 |
| G-08 | 3-3 금수 | 한 수로 **열린 3**이 두 개 이상 동시에 생기는 수 (5장 정의) |
| G-09 | 4-4 금수 | 한 수로 **4**가 두 개 이상 동시에 생기는 수. 한 줄 안에서 4가 둘 생기는 경우도 포함 |
| G-10 | 장목 금수 | 한 수로 흑 돌이 6개 이상 연속되는 수 |
| G-11 | 무승부 | 판이 모두 차고 승자가 없으면 무승부 |
| G-12 | 시간패 | 턴 제한 시간 안에 두지 않으면 그 사람이 진다 (봇이 맡은 자리는 해당 없음) |
| G-13 | 리매치 | 같은 방에서 다시 시작한다. 흑 결정은 방 옵션을 다시 적용한다 (무작위면 다시 뽑는다) |
| G-14 | 합의 무승부 | 한쪽이 무승부를 제안하고 상대가 수락하면 판이 무승부로 끝난다 (결과 `agreed`). 판이 다 차서 끝나는 G-11과 구분해 기록한다 |
| G-15 | 제안 시기 | 제안은 **자기 차례에만**, **서로 30수씩(전체 60돌) 이상 둔 뒤**에 할 수 있다. 거절당하면 그 제안자는 **자기 수를 10번 더 둘 때까지**(전체 20돌 뒤) 다시 제안할 수 없다. 한 판에서의 제안 횟수는 따로 제한하지 않는다 (2026-11-28 결정) |
| G-16 | 제안 응답 | 상대에게 수락 / 거절 버튼이 뜬다. 15초 안에 답이 없거나 상대가 나가거나 끊기면 거절로 본다. 제안이 대기 중인 동안 제안자의 턴 타이머는 멈추고, 답이 오면 남은 시간으로 이어서 둔다 (거절·응답 없음), 수락이면 바로 끝난다. 응답하는 쪽의 자기 턴은 아직 오지 않았으므로 타이머는 없다 |

## 3. 진행

1. 대기실: 방장이 옵션(금수, 흑 정하기, 턴 시간)을 고른다. 2명이 되면(또는 빈자리 봇) 방장이 시작한다.
2. 시작: 옵션에 따라 흑과 백을 정하고 모두에게 알린다.
3. 대국: 흑부터 번갈아 둔다. 수마다 서버가 G-03, G-07을 검사하고 G-04, G-05, G-11로 끝났는지 판정한다.
4. 종료: 승리(오목), 시간패, 무승부 중 하나로 끝나고 결과 화면을 보여 준다. 승리한 다섯 돌을 표시한다.

## 4. 방 옵션

| 옵션 | 값 | 기본값 | 비고 |
| --- | --- | --- | --- |
| 흑 정하기 | 방장 / 상대 / 무작위 | 무작위 | 상대가 봇이면 봇이 흑일 수 있다 |
| 흑 3-3 금지 | 켜기 / 끄기 | 켜기 | |
| 흑 4-4 금지 | 켜기 / 끄기 | 켜기 | |
| 흑 장목 금지 | 켜기 / 끄기 | 켜기 | 세 금수 기본값 = 렌주 규칙 |
| 턴 제한 시간 | 15 / 30 / 60초 | 30초 | 거짓말쟁이 주사위와 같은 선택지 |
| 봇으로 빈자리 채우기 | 켜기 / 끄기 | 켜기 | |
| 비공개 방 | 켜기 / 끄기 | 켜기 | |

- 세 금수를 모두 켜면 렌주 규칙과 같고, 모두 끄면 자유 오목이다. 대기실에는 이 조합을 "자유 오목 / 렌주"처럼 한눈에 알 수 있게 보여 준다.
- 옵션은 대기실에서만 바꿀 수 있다 (게임 중 변경 불가).

## 5. 금수 판정 정의

모두 **흑이 방금 둔 돌을 지나는 네 방향(가로, 세로, 두 대각선)**만 본다.

- **5**: 같은 색 돌이 정확히 5개 연속.
- **4**: 빈칸 하나에 흑을 더 두면 정확히 5가 되는 돌 모양. 막힌 4(한쪽이 막힘)와 열린 4를 모두 포함한다.
- **열린 4**: 양쪽 어느 끝에 두어도 정확히 5가 되는 연속 4개.
- **열린 3**: 빈칸 하나에 흑을 더 두면 **열린 4**가 되는 돌 모양 (띈 3 포함). 단, 그 빈칸에 두는 수가 금수이면 열린 3으로 세지 않는다 (렌주의 재귀 판정).
- 판정 순서: G-06(정확히 5) → G-10(장목) → G-09(4-4) → G-08(3-3).
- 재귀 판정이 매우 깊어지는 드문 모양은 구현에서 깊이를 제한할 수 있다. 제한 깊이와 그 영향은 구현 PR에 적는다.

## 6. 메시지 프로토콜 (오목에서 다른 것)

공통 대기실 메시지(`set_ready`, `start_game`, `set_options`, `add_bot`, `remove_bot`, `kick_player`, `rematch`, `leave_room`)는 거짓말쟁이 주사위와 같다.

### 클라이언트 → 서버

| 이벤트 | 페이로드 | 허용 상태 | 거부 조건 |
| --- | --- | --- | --- |
| `offer_draw` | turnId | PLAYING | 내 차례 아님(`NOT_YOUR_TURN`), 지난 turnId(`STALE_TURN`), 30수 전·거절 뒤 대기 중·이미 제안 중·상대가 봇(`INVALID_STATE`) |
| `answer_draw` | accept (불리언) | PLAYING | 대기 중인 제안이 없음(`INVALID_STATE`), 제안한 본인(`NOT_YOUR_TURN`) |
| `place` | x, y (0~14), turnId | PLAYING | 내 차례 아님(`NOT_YOUR_TURN`), 범위 밖(`INVALID_MOVE`), 빈칸 아님(`OCCUPIED`), 금수(`FORBIDDEN_MOVE`), 만료된 turnId(`STALE_TURN`) |

### 서버 → 클라이언트

| 이벤트 | 대상 | 내용 |
| --- | --- | --- |
| 공유 상태 | 전체 | 판(225칸), 흑·백 플레이어, 현재 차례, 마감 시각, 수 순서, 상태. 오목에는 숨길 정보가 없다 |
| `turn_start` | 전체 | playerId, turnId, 마감 시각 |
| `stone_placed` | 전체 | 색, x, y, 몇 번째 수, 봇 여부 |
| `player_replaced` | 전체 | playerId, 이유(`left` 나감 / `disconnected` 연결 끊김 / `returned` 돌아옴). 상대 화면에 알림을 띄운다 |
| `draw_offered` | 전체 | 제안자 playerId, 응답 마감 시각(서버 시간) |
| `draw_declined` | 전체 | 제안자 playerId, 이유(`declined` 거절 / `timeout` 응답 없음 / `gone` 나감·끊김) |
| `game_over` | 전체 | 결과(`five` 오목 / `timeout` 시간패 / `draw` 판이 다 참 / `agreed` 합의 무승부), 승자, 승리한 다섯 돌 좌표 |

## 7. 시간, 퇴장, 재접속, 봇

| ID | 영역 | 규칙 |
| --- | --- | --- |
| G-20 | 시간 | 마감 시각은 서버 기준. 클라이언트 타이머는 표시용 (거짓말쟁이 주사위 S-05와 같다) |
| G-21 | 시간패 | 마감까지 착수가 없으면 차례인 사람이 시간패 (G-12) |
| G-22 | 퇴장 | 게임 중 스스로 나가면 **바로 봇이 그 색을 이어서 둔다.** 상대에게 "○○ 님이 나가서 봇이 이어서 둡니다"를 알린다 |
| G-23 | 연결 끊김 | 60초 동안 자리를 유지하고 상대에게 "연결 끊김"을 보여 준다. **턴 시간은 그대로 흐르고, 마감까지 돌아와 두지 않으면 시간패(G-21)**다. 60초 안에 돌아오면 그대로 이어서 둔다. 60초가 지나도 판이 끝나지 않았으면 G-22처럼 봇이 이어서 둔다 |
| G-24 | 봇 | 서버 안에서 돈다. 이길 수 있는 수 → 상대의 4·열린 3 막기 → 연결 수 평가 순으로 둔다. 1~2초 지연 후 착수. 금수를 두지 않는다 |
| G-25 | 봇의 시간 | 봇이 맡은 자리는 시간패가 없다 |
| G-26 | 봇과 무승부 | 봇이 맡은 자리(처음부터 봇이거나 사람이 나가 봇이 이어받은 자리)는 제안하지 않고, 제안을 받으면 바로 거절한다. 그래서 상대가 봇이면 제안 버튼을 끄고 "봇은 무승부를 받지 않아요"를 보여 준다. 시간 초과가 이어져 자동으로 두는 사람(autopilot)은 사람이므로 직접 응답한다 |

### 착수 입력 (G-30~)

입력마다 포인터 종류(`pointerType`)로 동작을 나눈다. 기기 판별이 아니라 입력 종류로 나누므로 터치 노트북, 마우스를 연결한 태블릿에서도 맞게 동작한다.

| ID | 입력 | 동작 |
| --- | --- | --- |
| G-30 | 마우스 (`mouse`) | 호버한 교차점에 반투명 돌을 보여 준다. 클릭하면 착수. 판 밖으로 나가면 반투명 돌을 지운다 |
| G-31 | 터치 (`touch`) | 첫 터치: 그 교차점에 반투명 돌 + 그 줄과 칸 강조 + "H8에 둘까요?" 안내. 같은 교차점을 다시 터치하면 착수. 다른 교차점을 터치하면 반투명 돌이 옮겨 간다 |
| G-32 | 펜 (`pen`) | 호버 이벤트가 오면 G-30, 오지 않으면 G-31 |
| G-33 | 키보드 | 방향키로 반투명 돌 이동, Enter로 착수 (접근성) |
| G-34 | 표시 조건 | 반투명 돌은 내 차례이고 둘 수 있는 빈칸에서만 보인다. 켜진 금수 자리는 빨간 X로 보여 주고 착수할 수 없다 |
| G-35 | 선택 해제 | 차례가 넘어가거나, 상대가 그 자리에 두거나, 게임이 끝나면 반투명 돌을 지운다 |
| G-36 | 판 터치 | 판 위에서는 화면 스크롤과 확대가 일어나지 않게 막는다 |
| G-38 | 무승부 제안 UI | 제안 버튼은 "무승부 제안"(조건이 안 되면 꺼짐, 이유를 한 줄로: "30수 이후 제안할 수 있어요" / "잠시 뒤 다시 제안할 수 있어요"). 제안하면 "무승부를 제안했어요 · 기다리는 중"과 응답 타이머. 받는 쪽은 판 아래에 "○○ 님이 무승부를 제안했어요"와 수락 / 거절 버튼(15초). 판은 계속 보이고 오착수가 없게 판 입력은 막지 않지만, 제안이 오면 터치 미리보기 선택은 지운다 |
| G-37 | 알림 | `player_replaced`를 받으면 상단에 알림을 띄우고 그 사람 자리에 "봇이 대신" 표시 |

착수는 서버가 최종 판정한다. 클라이언트의 금수 표시는 같은 룰 함수(`packages/rules`)를 써서 미리 보여 줄 뿐이다.

## 10. 기록 (DB)

판이 끝날 때 **판 요약**만 한 번에 저장한다 (마이그레이션 `002_game_type_summary`).

- `games`: `game_type = 'gomoku'`, `options`(금수 3-3/4-4/장목, 흑 정하기, 턴 시간, 봇 채우기), `end_reason`(`five` / `timeout` / `draw` / `agreed`), `summary`(JSON: `result`, `winnerColor`, `moveCount`, `botMoveCount`, `hasBot`)
- `game_players`: 자리 0 = 흑, 1 = 백. 이긴 쪽 순위 1, 진 쪽 2, 무승부(`draw`, `agreed`)면 둘 다 1. 처음부터 봇인 자리는 `player_id`가 비어 있다
- 수 순서(좌표)는 저장하지 않는다. 계정이 없어 복기할 사람이 없고, 지금 필요한 것은 운영 통계(판 수, 완주율, 시간패 비율, 금수 설정별 흑 승률)다
- 나중에 복기 링크나 리플레이 검증이 필요해지면 `gomoku_moves(game_id, move_no, color, x, y, is_bot)` 테이블을 새 마이그레이션으로 추가한다
