# 업다운 숫자폭탄(updown-bomb) 명세서 v0.1

- 작성일: 2026-11-27
- 상태: 초안. "결정 필요" 항목을 정한 뒤 화면 시안을 보여 주고 구현한다
- 화면 이름: **업다운 숫자폭탄** / 코드·주소 이름: **`updown-bomb`** (`/updown-bomb`, `/updown-bomb/r/<코드>`, 방 종류 `updown_bomb`)
- 공통 구조(방 코드, 대기실, 재접속, 봇 대체, 추방, 이탈 기록, 리매치)는 ADR 0003 공통 엔진과 `liars-dice.md`를 따른다. 이 문서는 업다운에서 다른 점만 적는다
- 출처: 누구나 아는 "업다운" 놀이 규칙. 사내 동료의 WHO? 페이지에서 후보로 골랐지만 코드, 문구, 그림은 가져오지 않는다
- **WMG 첫 파티 게임**이다. 이긴 사람이 아니라 **당첨자(벌칙을 받을 사람) 1명**을 뽑는다. 파티 게임 공통(카테고리, 결과 화면, 기록 방식)은 9장에 적고, 뒤에 붙는 파티 게임(풍선 터뜨리기, 보물 찾기)도 따른다

## 1. 개요

모두가 모르는 폭탄 숫자 하나가 범위 안에 숨어 있다. 차례대로 숫자를 하나씩 말하면 서버가 "업"(폭탄이 더 큼) 또는 "다운"(더 작음)으로 범위를 좁힌다. 폭탄 숫자를 말한 사람이 당첨되고 판이 바로 끝난다.

| 항목 | v1 결정 |
| --- | --- |
| 인원 | 2~6명 (봇 포함) + 관전 |
| 범위 | 1~100 (방 옵션, UD-01) |
| 당첨 | **1명. 당첨자가 나오면 바로 끝** (2026-11-27 결정) |
| 첫 차례 | 무작위 |
| 턴 제한 시간 | 15초 (방 옵션) |
| 시간 초과 | 서버가 범위 안의 숫자를 대신 말한다. 2번 연속이면 봇이 대신 진행 (UD-12) |
| 게임 중 퇴장 | 봇이 이어서 한다. 다른 사람에게 알린다 (공통) |
| 목표 플레이 시간 | 1~3분 |
| 베팅 / 재화 | 없음 |

## 2. 규칙

| ID | 규칙 | 상세 |
| --- | --- | --- |
| UD-01 | 범위와 폭탄 | 판이 시작될 때 서버가 범위(기본 1~100) 안에서 폭탄 숫자 하나를 `crypto.randomInt`로 고른다. 판이 끝날 때까지 바뀌지 않는다 |
| UD-02 | 차례 | 첫 차례는 무작위. 그다음은 좌석 번호 순(시계 방향) |
| UD-03 | 말하기 | 자기 차례에 지금 범위(낮은 값 ~ 높은 값, 양 끝 포함) 안의 정수 하나를 말한다. 범위 밖이면 거부 (`OUT_OF_RANGE`, 상태 변화 없음) |
| UD-04 | 업 | 말한 수가 폭탄보다 작으면 범위의 낮은 값을 (말한 수 + 1)로 올린다 |
| UD-05 | 다운 | 말한 수가 폭탄보다 크면 범위의 높은 값을 (말한 수 − 1)로 내린다 |
| UD-06 | 당첨 | 말한 수가 폭탄이면 그 사람이 당첨되고 판이 바로 끝난다. 폭탄 숫자와 모든 기록을 공개한다 |
| UD-07 | 마지막 한 숫자 | 범위에 숫자가 하나만 남으면(그 수가 폭탄) 다음 차례인 사람은 고를 수 없으므로 **바로 당첨** 처리하고 끝낸다 (`forced`). **결정 필요 ①** |
| UD-08 | 리매치 | 같은 방 대기실로. 새 판에서는 폭탄과 첫 차례를 다시 뽑는다 |

### 예시 (3명, 범위 1~100, 폭탄 42)

| 순서 | 말한 수 | 결과 | 남은 범위 |
| --- | --- | --- | --- |
| A | 50 | 다운 | 1~49 |
| B | 20 | 업 | 21~49 |
| C | 40 | 업 | 41~49 |
| A | 45 | 다운 | 41~44 |
| B | 42 | **폭탄** | B 당첨, 끝 |

## 3. 진행

```
WAITING → STARTING(3초) → PLAYING ⟲(말하기) → GAME_OVER → (리매치) → WAITING
```

- STARTING: 좌석 확정, 폭탄과 첫 차례 뽑기
- PLAYING: 차례마다 `turn_start` → 말하기(또는 시간 초과 대신 말하기) → `number_called`
- GAME_OVER: 당첨자, 폭탄 숫자, 전체 기록 공개. 리매치 가능

## 4. 방 옵션

| 옵션 | 값 | 기본값 | 비고 |
| --- | --- | --- | --- |
| 범위 | 1~50 / 1~100 / 1~200 | 1~100 | **결정 필요 ②** (고정 1~100으로 둘 수도 있음) |
| 최대 인원 | 2~6 | 6 | 지금 인원보다 줄일 수 없다 (원카드와 같다) |
| 턴 제한 시간 | 10 / 15 / 30초 | 15초 | 다른 게임(15/30/60)보다 짧다. **결정 필요 ③** |
| 봇으로 빈자리 채우기 | 켜기 / 끄기 | 켜기 | |
| 비공개 방 | 켜기 / 끄기 | 켜기 | |

당첨 인원은 옵션으로 두지 않는다. 늘 1명이다 (2026-11-27 결정).

| ID | 규칙 |
| --- | --- |

## 6. 메시지 (공통과 다른 것)

### 클라이언트 → 서버

| 이벤트 | 페이로드 | 거부 |
| --- | --- | --- |
| `call_number` | `value`, `turnId` | `NOT_YOUR_TURN`, `STALE_TURN`, `OUT_OF_RANGE`(정수가 아니거나 범위 밖) |

### 서버 → 클라이언트

| 이벤트 | 대상 | 내용 |
| --- | --- | --- |
| `number_called` | 전체 | `playerId`, `value`, `result: 'up' \| 'down' \| 'bomb'`, 새 `low`, `high`, `isAuto`, `isBot` |
| `game_over` | 전체 | `loserId`(당첨자), `bomb`, `forced`(UD-07로 끝났는지) |
| 공통 | | `welcome`, `turn_start`, `player_replaced`, `error` |

공유 상태: `phase, roomCode, hostId, options, players(공통 필드 + seat, autopilot, replaced), low, high, history[](playerId, value, result, isAuto), currentTurn, turnId, deadline, phaseEndsAt, loserId, bomb(끝난 뒤에만 채움), forced`.

## 7. 시간, 퇴장, 재접속, 봇

| ID | 영역 | 규칙 |
| --- | --- | --- |
| UD-10 | 시간 | 마감 시각은 서버 기준 (S-05와 같다) |
| UD-11 | 퇴장·끊김 | 공통: 끊겨도 시간은 흐르고, 60초가 지나거나 스스로 나가면 봇이 이어받는다 |
| UD-12 | 시간 초과 | 마감까지 말하지 않으면 서버가 **범위 안에서 무작위로 고른 숫자**를 대신 말한다(`isAuto`). 2번 연속이면 봇이 대신 진행하고, 직접 말하면 돌려받는다. **결정 필요 ④** (대안: 시간 초과 = 바로 당첨) |
| UD-13 | 봇 | 서버 안에서 돈다. 지금 범위 안에서 무작위로 고른다(폭탄을 모르므로 어떤 수든 당첨 확률이 같다). 1~2초 지연 |
| UD-14 | 봇의 시간 | 봇이 맡은 자리는 시간 초과가 없다 |

무작위로 고르는 이유: 어느 숫자를 말해도 그 차례에 당첨될 확률은 똑같이 (1 ÷ 남은 숫자 수)다. 서버가 대신 말할 때 특정 숫자(가운데 등)를 고르면 다음 사람에게 유리하거나 불리해질 수 있어서 무작위로 둔다.

## 8. 화면

| 화면 | 구성 | 비고 |
| --- | --- | --- |
| 대기실 | 공통 대기실 + 옵션(범위, 최대 인원, 턴 시간) | `renderWaitingShell` |
| 게임 | 가운데에 **남은 범위를 크게**(예: `41 ~ 49`), 범위 막대(전체 대비 남은 구간), 참가자 줄(차례·타이머·봇 표시), 숫자 입력(키패드), 최근 기록(누가 몇을 말해 업/다운) | 360px 한 손 조작. **시안을 먼저 보여 준다** |
| 당첨 | 폭탄 숫자 공개 연출, 당첨자 크게, 전체 기록, 다시 하기 / 나가기 | 파티 게임 공통 결과 화면 (9장) |

입력: 범위 안의 숫자만 누를 수 있게 키패드를 막는다(범위 밖이면 "말하기" 버튼이 꺼짐). 클라이언트 검사는 편의일 뿐이고 판정은 서버가 한다 (원칙 1).

## 9. 파티 게임 공통 (이 게임에서 처음 정한다)

| 항목 | 결정 |
| --- | --- |
| 카테고리 | `party` (화면 이름 "파티"). 메인 화면 검색·필터의 칩으로도 쓴다 |
| 결과 | 승자 대신 **당첨자 1명**. 결과 화면 제목은 본인이면 "당첨!", 아니면 "통과!", 관전자에게는 "○○ 님 당첨" |
| 순위 기록 | 당첨자 = 2위, 나머지 = 1위 (`game_players.final_rank`). 통계에서 "당첨"을 진 사람과 같게 센다 |
| 문구 | 벌칙 내용(커피 사기 등)은 사이트가 정하지 않는다. 내기·돈과 엮는 문구를 쓰지 않는다 (CLAUDE.md) |

## 11. 기록 (DB)

판 요약(ADR 0002, `games.summary`): 범위, 폭탄 숫자, 말한 횟수(`moveCount`), 대신 말한 횟수(`autoMoveCount`), `forced` 여부, 봇 여부. `/stats` 게임별 지표: 평균 말한 횟수, 시간 초과로 대신 말한 비율, 마지막 한 숫자로 끝난 판 비율.

## 12. 대표 테스트

| TC | 참조 | 내용 |
| --- | --- | --- |
| UT-01 | UD-01 | 폭탄은 범위 안이고, 시드를 바꾸면 범위 전체에 고르게 나온다 |
| UT-02 | UD-03 | 범위 밖·소수·문자는 `OUT_OF_RANGE`, 상태 그대로 |
| UT-03 | UD-04, UD-05 | 업이면 낮은 값, 다운이면 높은 값이 바뀐다 (경계값 포함) |
| UT-04 | UD-06 | 폭탄을 말하면 그 사람이 당첨되고 바로 끝난다 |
| UT-05 | UD-07 | 숫자 하나만 남으면 다음 차례인 사람이 바로 당첨 (`forced`) |
| UT-06 | UD-20 | 끝나기 전에는 어떤 공유 상태·메시지에도 폭탄 숫자가 없다 (TC-08과 같은 검사) |
| UT-07 | UD-12 | 시간 초과면 대신 말하고(`isAuto`), 2번 연속이면 봇 진행, 직접 말하면 돌려받는다 |
| UT-08 | UD-13 | 봇끼리 1,000판 모두 끝나고, 봇은 늘 범위 안의 숫자만 말한다 |
| UT-09 | 공통 | 사람 1명 + 봇으로 한 판 완주 (E2E), 360px에서 키패드가 다 보인다 |
