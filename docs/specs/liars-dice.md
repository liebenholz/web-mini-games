# 거짓말쟁이 주사위 게임 명세서 v0.1

- 작성일: 2026-11-22
- 원본: 기획 문서(Claude Docs)에서 저장소용으로 옮긴 사본. 이후 변경은 이 파일에서 PR로 관리한다.

## 1. 개요

2~6명이 각자 자기 주사위만 보고, 테이블 전체에 특정 눈이 몇 개 있는지 선언하면서 상대의 거짓말을 잡아내는 심리전 게임이다. 웹 미니게임 플랫폼의 첫 게임이며, 공통 프레임워크(방, 턴, 재접속, 봇)를 검증하는 역할도 한다.

| 항목 | v1 결정 |
| --- | --- |
| 인원 | 2~6명 (봇 포함) |
| 주사위 | 1인당 6면체 5개 |
| 목표 플레이 시간 | 한 판 5~10분 (테스트로 보정) |
| 1 와일드 | 켜짐 (1은 모든 눈으로 센다). 1에 대한 선언은 v1에서 금지 |
| 턴 제한 시간 | 기본 30초 (방 옵션) |
| 판정 구조 | 서버 권한형. 다른 사람의 주사위는 공개 전까지 서버에만 있음 |
| 승리 조건 | 마지막까지 주사위가 남은 1명 |
| 베팅 / 재화 | 없음 |

## 2. 게임 진행 방식

한 판은 여러 라운드로 이루어지고, 라운드마다 한 명이 주사위 1개를 잃는다. 주사위가 0개가 된 플레이어는 탈락하고, 마지막 1명이 남으면 게임이 끝난다.

1. **굴리기:** 서버가 생존자의 주사위를 동시에 굴린다. 각자 자기 주사위만 본다.
2. **선언:** 선부터 시계 방향으로 "테이블 전체에 ○이 △개 이상 있다"고 선언한다.
3. **상향 또는 라이어:** 다음 차례는 더 높은 선언을 하거나, 직전 선언자에게 "라이어!"를 외친다.
4. **공개와 판정:** 라이어가 나오면 모든 주사위를 공개하고 선언된 눈의 개수를 센다. 1은 와일드로 함께 센다.
5. **패널티:** 실제 개수 ≥ 선언 개수면 라이어를 외친 사람이, 아니면 선언자가 주사위 1개를 잃는다.
6. **다음 라운드:** 주사위를 잃은 사람이 다음 라운드의 선이 된다.

### 예시 라운드 (3인, 총 15개)

| 플레이어 | 주사위 | "3"으로 세는 개수 (1 포함) |
| --- | --- | --- |
| A | 1, 2, 3, 3, 5 | 3 |
| B | 2, 3, 4, 6, 6 | 1 |
| C | 1, 3, 5, 5, 6 | 2 |

| 순서 | 행동 | 비고 |
| --- | --- | --- |
| 1 | A: "3이 4개" | |
| 2 | B: "3이 5개" | 개수 증가 |
| 3 | C: "5가 5개" | 같은 개수, 더 높은 눈 |
| 4 | A: "3이 6개" | 개수 증가, 눈 전환 |
| 5 | B: "라이어!" | |
| 6 | 공개 | 3으로 세는 주사위 = 6개 → 선언 성공 |
| 7 | 패널티 | B가 1개 잃음 (5 → 4), 다음 라운드 선은 B |

모르는 주사위 하나가 특정 눈(2~6)으로 셀 확률은 1/3이다 (그 눈 또는 1). 봇 로직은 이 기대값을 쓴다 (S-11).

## 3. 기본 룰

| ID | 규칙 | 상세 |
| --- | --- | --- |
| R-01 | 구성 | 1인당 6면체 주사위 5개로 시작 (방 옵션 3~5). 주사위 수 = 남은 목숨 |
| R-02 | 좌석과 턴 순서 | 입장 순서대로 좌석 배정, 좌석 번호 오름차순(시계 방향)으로 진행 |
| R-03 | 첫 라운드 선 | 서버가 무작위로 선정 |
| R-04 | 이후 라운드 선 | 직전 라운드에서 주사위를 잃은 플레이어. 탈락했으면 시계 방향 다음 생존자 |
| R-05 | 선언 형식 | (개수, 눈). 눈은 2~6만 가능. 개수는 1 이상, 현재 테이블 총 주사위 수 이하 |
| R-06 | 첫 선언 | 라운드의 선은 반드시 선언해야 하며 라이어를 외칠 수 없음 |
| R-07 | 상향 규칙 | 새 선언은 ① 개수가 더 많거나(눈은 자유), ② 개수가 같고 눈이 더 커야 함 |
| R-08 | 라이어 | 자기 차례에만, 직전 선언자에게만 외칠 수 있음 |
| R-09 | 1 와일드 | 공개 시 1은 선언된 눈으로 함께 센다 |
| R-10 | 판정 | 실제 개수 ≥ 선언 개수 → 라이어를 외친 사람이 1개 잃음. 실제 < 선언 → 선언자가 1개 잃음 |
| R-11 | 상향 불가 | 직전 선언이 (총 주사위 수, 6)이면 다음 플레이어는 라이어만 가능 |
| R-12 | 탈락 | 주사위 0개가 되면 탈락, 관전 모드로 전환 |
| R-13 | 승리와 순위 | 마지막 생존자가 1위. 나머지는 나중에 탈락한 순서대로 순위 |

### v1.1 이후 방 옵션 (v1 미구현)

- **1 선언 허용:** 1로 전환할 때는 직전 개수의 절반(올림) 이상, 1에서 다른 눈으로 돌아갈 때는 직전 개수 × 2 + 1 이상. 1 선언에는 와일드가 적용되지 않는다.
- **정확히 맞추기(Spot on):** 라이어 대신 "정확히!"를 선언. 실제 개수가 선언 개수와 같으면 나머지 모두 1개씩 잃고, 틀리면 "정확히!"를 외친 사람이 1개를 잃는다.

## 4. 방 옵션과 로비

| 옵션 | 값 범위 | 기본값 | v1 |
| --- | --- | --- | --- |
| 최대 인원 | 2~6 | 6 | O |
| 봇으로 빈자리 채우기 | 켜기 / 끄기 | 켜기 | O |
| 턴 제한 시간 | 15 / 30 / 60초 | 30초 | O |
| 시작 주사위 수 | 3~5 | 5 | O |
| 비공개 방 | 켜기 / 끄기 | 켜기 | O |
| 1 선언 허용 | 켜기 / 끄기 | 끄기 | X (v1.1) |
| 정확히 맞추기 | 켜기 / 끄기 | 끄기 | X (v1.1) |

- 방 코드는 영문 대문자와 숫자 6자리. 혼동되는 문자(0, O, 1, I)는 쓰지 않는다.
- 모두 준비하면 방장이 시작한다. 최소 2명(봇 포함).
- 방장이 나가면 가장 먼저 입장한 사람이 방장을 이어받는다.
- 게임 중에는 새로 참여할 수 없고 관전만 가능하다. 관전자는 공개 전 주사위를 볼 수 없다.
- 게임이 끝나면 같은 방에서 리매치할 수 있다.

## 5. 서버 상태 머신

```
WAITING → STARTING → ROLLING → BIDDING ⟲(선언)
                        ↑          │ 라이어
                        │          ↓
           (생존자 ≥ 2) └── RESOLVE ← REVEAL
                               │ (생존자 = 1)
                               ↓
                           GAME_OVER → (리매치) → WAITING
```

| 상태 | 하는 일 | 다음 상태 조건 |
| --- | --- | --- |
| WAITING | 입장, 준비, 방 옵션 설정 | 방장이 시작(2명 이상, 전원 준비) → STARTING |
| STARTING | 3초 카운트다운, 좌석 확정, 첫 선 무작위 선정 | 카운트다운 종료 → ROLLING |
| ROLLING | 생존자 주사위 굴림, 각자에게 `your_dice` 전송, 라운드 로그 기록 | 즉시 → BIDDING |
| BIDDING | 차례대로 선언 접수, 턴 타이머 운영 | 선언 → 다음 차례(BIDDING 유지) / 라이어 → REVEAL |
| REVEAL | 전체 주사위 공개, 개수 집계, 판정 | 공개 연출 3초 후 → RESOLVE |
| RESOLVE | 패배자 주사위 1개 차감, 탈락 처리, 다음 선 결정 | 생존자 2명 이상 → ROLLING / 1명 → GAME_OVER |
| GAME_OVER | 순위 확정, 전적 저장 | 리매치 → WAITING / 전원 퇴장 → 방 종료 |

## 6. 메시지 프로토콜

모든 메시지에는 `roomId`, `roundNo`, `seq`(서버 증가 번호)를 포함해 순서 역전과 중복을 막는다.

### 클라이언트 → 서버

| 이벤트 | 페이로드 | 허용 상태 | 거부 조건 |
| --- | --- | --- | --- |
| `join_room` | roomCode, nickname | WAITING | 방 없음, 인원 초과, 게임 중(관전으로 전환) |
| `set_ready` | ready: bool | WAITING | — |
| `start_game` | — | WAITING | 방장 아님, 2명 미만, 미준비 인원 있음 |
| `bid` | quantity, face, turnId | BIDDING | 내 차례 아님, R-05/R-07 위반, 만료된 turnId |
| `call_liar` | turnId | BIDDING | 내 차례 아님, 직전 선언 없음(R-06) |
| `leave_room` | — | 모든 상태 | — |
| `rematch` | — | GAME_OVER | — |
| `set_options` | options(부분) | WAITING | 방장 아님(NOT_HOST), 범위 밖(INVALID_OPTIONS) |
| `add_bot` | — | WAITING | 방장 아님, 자리 없음(ROOM_FULL) |
| `remove_bot` | playerId | WAITING | 방장 아님, 봇이 아님 |
| `kick_player` | playerId | WAITING | 방장 아님(NOT_HOST), 대상이 사람이 아니거나 본인(INVALID_MESSAGE) |

`join_room`은 Colyseus 매칭(create / joinById / joinOrCreate)으로 처리하며 입장 옵션은 guestId, nickname, (만들 때) options다. 대기실 조작(`set_options`, `add_bot`, `remove_bot`, `kick_player`)은 8장 대기실 UI를 위해 추가했다 (ADR 0001, 추방은 E-15).

### 서버 → 클라이언트

| 이벤트 | 대상 | 내용 |
| --- | --- | --- |
| `welcome` | 본인만 | 공개 playerId, 역할(player/spectator). 게스트 ID는 공개하지 않음 |
| `room_state` | 전체 | 플레이어 목록, 각자 남은 주사위 개수, 현재 상태, 선언 기록. **다른 사람의 주사위 눈은 없음** |
| `your_dice` | 본인만 | 내 주사위 눈 배열 |
| `turn_start` | 전체 | playerId, turnId, 마감 시각(서버 시간) |
| `bid_made` | 전체 | playerId, quantity, face, 자동 행동 여부 |
| `liar_called` | 전체 | caller, target |
| `reveal` | 전체 | 모든 플레이어의 주사위, 선언 눈으로 센 개수, 판정 결과 |
| `dice_lost` | 전체 | playerId, 남은 개수 |
| `player_eliminated` | 전체 | playerId, 순위 |
| `game_over` | 전체 | 최종 순위 |
| `error` | 요청자 | 에러 코드, 메시지 |

`turnId`는 턴마다 새로 발급한다. 타임아웃 자동 행동 뒤에 늦게 도착한 입력은 `STALE_TURN`으로 거부한다.

## 7. 정보 은닉, 난수, 타임아웃, 재접속, 봇

| ID | 영역 | 규칙 |
| --- | --- | --- |
| S-01 | 정보 은닉 | 주사위 눈은 `your_dice`로 본인에게만 보낸다. `reveal` 전에는 어떤 브로드캐스트에도 다른 사람의 눈을 넣지 않는다 |
| S-02 | 정보 은닉 | 관전자와 탈락자도 공개 전에는 눈을 볼 수 없다 |
| S-03 | 난수 | 서버에서 `crypto.randomInt`로 굴린다 |
| S-04 | 난수 | 라운드마다 굴린 결과를 로그에 남겨 리플레이 가능하게 한다. 시드 주입은 테스트 환경에서만 허용한다 |
| S-05 | 타임아웃 | 마감 시각은 서버 시간 기준. 클라이언트 타이머는 표시용 |
| S-06 | 타임아웃 | 시간 초과 시 자동 행동: 직전 선언이 없으면 "2가 1개", 있으면 가장 낮은 합법적 상향, 상향 불가(R-11)면 라이어 |
| S-07 | 타임아웃 | 2턴 연속 타임아웃이면 봇이 대신 플레이. 플레이어가 입력하면 다시 돌려받음 |
| S-08 | 재접속 | 연결이 끊기면 60초 동안 자리를 유지. 그 사이 차례가 오면 S-06 적용 |
| S-09 | 재접속 | 돌아오면 `room_state` 전체와 본인의 `your_dice`를 다시 보낸다 |
| S-10 | 이탈 | 60초가 지나거나 스스로 나가면 봇이 남은 주사위를 이어받는다. 사람 1명 + 봇만 남았을 때의 처리는 미결정 |
| S-11 | 봇 | 기대 개수 = 내 해당 개수 + 남의 주사위 수 ÷ 3. 직전 선언 개수가 기대 개수 + 여유치를 넘으면 라이어, 아니면 내가 가장 많이 가진 눈으로 최소 상향 |
| S-12 | 봇 | 봇은 자기 주사위와 공개 정보만 사용한다. 1~3초 지연 후 행동한다 |

## 8. 클라이언트 UI

| 화면 | 구성 요소 | 비고 |
| --- | --- | --- |
| 로비 | 닉네임 입력, 방 만들기, 방 코드로 입장, 랜덤 매칭 | 닉네임 2~12자 |
| 대기실 | 좌석 목록, 준비 상태, 방 옵션(방장만 편집), 방 코드 가리기·복사, 봇 추가, 참가자 추방(방장만, 확인 후), 시작 버튼 | 초대 링크 `/liars-dice/r/:code` 복사. 코드를 가려도 복사는 그대로 된다. 게임 중에는 방 코드를 보여 주지 않는다 |
| 게임 테이블 | 플레이어(닉네임, 남은 주사위 수, 차례 표시), 내 주사위, 현재 선언, 선언 기록, 턴 타이머 | 테이블 전체 주사위 수 항상 표시 |
| 선언 패널 | 개수 +/−, 눈 선택(2~6), 선언 버튼, 라이어 버튼 | 불가능한 값 비활성화, 가장 낮은 합법 선언을 기본값으로 |
| 공개 연출 | 모든 주사위 공개, 선언 눈과 1 강조, 합계 카운트, 패배자 표시 | 3초 후 자동 진행 |
| 결과 | 순위, 리매치, 로비로 | — |

- 로비, 대기실, 선언 패널은 DOM으로, 테이블과 연출은 Phaser 캔버스로 만든다.
- 모바일 세로 화면(360px 폭)에서 한 손으로 조작할 수 있어야 한다.
- 타이머가 5초 남으면 색상과 진동(모바일)으로 알린다.
- 연결이 끊기면 "재접속 중" 오버레이를 띄우고 자동으로 다시 연결한다.

## 9. 예외 처리

모든 거부는 요청한 클라이언트에게만 `error`로 알리고, 게임 상태는 바꾸지 않는다.

| ID | 상황 | 서버 처리 | 에러 코드 |
| --- | --- | --- | --- |
| E-01 | 직전보다 낮거나 같은 선언 | 거부 | INVALID_BID |
| E-02 | 개수가 테이블 총 주사위 수를 초과 | 거부 | INVALID_BID |
| E-03 | 눈이 1 또는 2~6 범위 밖 | 거부 | INVALID_BID |
| E-04 | 내 차례가 아닌데 선언·라이어 | 거부 | NOT_YOUR_TURN |
| E-05 | 라운드 첫 턴에 라이어 | 거부 | NO_BID_TO_CALL |
| E-06 | 같은 턴에 선언 두 번 전송 | 첫 입력만 처리 | STALE_TURN |

## 10. 데이터 저장

진행 중인 판은 서버 메모리에만 두고, 끝난 판과 라운드 기록만 PostgreSQL에 저장한다.

| 테이블 | 주요 컬럼 | 용도 |
| --- | --- | --- |
| `players` | id, nickname, created_at, last_seen_at | 플레이어 식별 (로그인 방식 미결정) |
| `games` | id, room_code, options(JSON), started_at, ended_at, end_reason | 판 단위 기록 |
| `game_players` | game_id, player_id, seat, is_bot, final_rank | 순위, 전적 |
| `rounds` | game_id, round_no, starter_seat, dice(JSON), result | 리플레이, 난수 분포 검증 |
| `bids` | game_id, round_no, seq, seat, quantity, face, is_auto, created_at | 선언 순서 복원, 타임아웃 분석 |

`rounds.dice`에는 공개 후의 값만 저장한다.

## 12. 미결정 사항
