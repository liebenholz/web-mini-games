# 클라이언트 오류 수집 명세서 v1

- 작성일: 2026-11-26
- 상태: 결정 반영 (2026-11-26)
- 관련: `docs/specs/stats.md` (같은 `/stats` 화면과 API에 붙인다)

## 1. 개요

사용자 브라우저(특히 모바일)에서 생긴 오류를 서버에서 날짜별로 센다. 지금은 사용자가 알려 주지 않으면 오류를 전혀 알 수 없다. 외부 서비스 없이 우리 서버에 모은다.

| 항목 | 결정 (2026-11-26) |
| --- | --- |
| 볼 수 있는 곳 | `/stats`에는 날짜별·종류별 **개수만**. 오류 문구는 운영 SQL로만 본다 (CE-09) |
| 저장 | 같은 오류끼리 묶어 하루 단위 개수와 대표 문구 하나만 남긴다 |
| 개인 정보 | 게스트 ID, 닉네임, 방 코드, IP, 전체 User-Agent는 보내지도 남기지도 않는다 |

## 2. 규칙

| ID | 규칙 | 상세 |
| --- | --- | --- |
| CE-01 | 수집 종류 | `js_error`(처리되지 않은 예외, `window.onerror`), `promise_rejection`(`unhandledrejection`), `connect_failed`(방 만들기·입장이 네트워크나 알 수 없는 이유로 실패. `ROOM_NOT_FOUND`, `ROOM_FULL`, `KICKED`처럼 서버가 정상적으로 거절한 것은 세지 않는다), `reconnect_failed`(연결이 끊긴 뒤 재접속을 포기함, S-08). 다른 출처 스크립트(확장 프로그램 등)가 내용 없이 보내는 `Script error.`는 세지 않는다 |
| CE-02 | 보내는 내용 | `kind`(CE-01), `message`(CE-03 처리 후), `game`(게임 id 또는 없음), `route`(`hub`·`stats`·`lobby`·`room`), `release`(클라이언트 빌드 커밋 앞 7자), `platform`(`ios`·`android`·`desktop`·`other` 중 하나). 이 밖의 값은 보내지 않는다 |
| CE-03 | 문구 정리 | 보내기 전에 브라우저에서 처리한다. URL의 쿼리와 `#` 뒤를 지운다. 방 코드 모양(영문 대문자·숫자 6자)을 `XXXXXX`로, 4자리 이상 숫자를 `#`으로 바꾼다. 200자에서 자른다 |
| CE-04 | 브라우저 쪽 제한 | 같은 종류와 문구는 화면을 연 동안 한 번만 보낸다. 한 번 연 화면에서 최대 10건까지만 보낸다. 실패해도 다시 보내지 않는다 (`keepalive` 전송) |
| CE-05 | 서버 검증 | `POST /client-error`. 형식이 틀리면 400 `INVALID_REPORT`. 서버가 문구를 다시 200자로 자르고 CE-03 치환을 한 번 더 한다 (클라이언트를 믿지 않는다) |
| CE-06 | 서버 쓰기 제한 | 새 보고는 1초에 20건까지만 받고 넘치면 버린다 (응답은 200). 같은 오류는 `(날짜, kind, game, 문구)`의 해시(지문)로 묶는다. 하루에 서로 다른 지문은 500개까지만 따로 세고, 넘치면 `kind`별 `other` 하나로 센다 |
| CE-07 | DB 쓰기 | 메모리에서 모았다가 1분마다 한 번에 쓴다 (원칙 8). 같은 지문이면 개수만 더한다. 서버가 꺼질 때 남은 것을 한 번 쓴다 |
| CE-08 | 공개 범위 | `/stats` 응답의 날짜마다 `clientErrors: { [kind]: 개수 }`만 더한다. 문구, 지문, release, platform은 넣지 않는다 (ST-07과 같은 원칙) |
| CE-09 | 운영 조회 | 문구, release, platform별 개수는 운영 문서의 SQL로 VM에서 본다 |

## 3. 화면 (`/stats`)

- 위 숫자 칸에 **오늘 오류**를 하나 더한다 (CE-01 네 종류의 합)
- **일일 오류** 그래프를 하나 더한다: 종류별로 쌓은 막대. 범례에 기간 합계. "표로 보기" 포함
- 오류가 없는 기간에는 "기간 안에 수집된 오류가 없습니다"를 보여 준다

## 4. 저장

- 마이그레이션 `004_daily_client_errors`:
  `daily_client_errors (day date, kind text, game text, fingerprint text, message text, release text, platform text, count int, PRIMARY KEY (day, fingerprint))`
  - `release`, `platform`은 그 지문을 처음 받은 값이다. 같은 오류가 여러 release에서 나면 첫 값만 남는다
- DB가 없는 개발·E2E 환경에서는 메모리에 센다
- 클라이언트 빌드에 `VITE_APP_RELEASE`로 커밋 해시를 넣고, 보고에는 앞 7자만 쓴다. 로컬 빌드는 `dev`

## 5. 테스트

- 문구 정리(CE-03): URL 쿼리, 방 코드, 긴 숫자, 200자 자르기
- 브라우저 제한(CE-04): 같은 오류 한 번, 최대 10건
- 서버: 형식 오류 400, 초당 제한, 지문 묶기, 500개 넘침, 1분 몰아쓰기, `/stats`에 문구가 없음 (CE-08)
- E2E: 화면에서 일부러 오류를 내면 `/stats` 오늘 오류가 1 늘어난다
