# 도둑잡기(thief) 명세서 v0.1

- 작성일: 2026-11-28
- 상태: 결정 반영 (2026-11-28). 화면 시안 확인 뒤 구현한다
- 화면 이름: **도둑잡기** / 코드·주소 이름: **`thief`** (`/thief`, `/thief/r/<코드>`, 방 종류 `thief`)
- 공통 구조(방 코드, 대기실, 재접속, 봇 대체, 추방, 이탈 기록, 리매치)는 ADR 0003 공통 엔진과 `liars-dice.md`를 따른다. 이 문서는 도둑잡기에서 다른 점만 적는다
- 카테고리는 `party`(파티). 결과, 순위 기록, 문구는 `updown-bomb.md` 9장을 따른다 (당첨 1명 = 2위, 나머지 = 1위. 내기·돈과 엮는 문구 금지)
- 이름: 오래된 전통 카드놀이 이름이다. 다른 회사 게임의 이름·아트는 쓰지 않는다 (CLAUDE.md)
- 이 게임은 **카드 게임이라 숨긴 정보(패)가 있다**. 원칙 4와 원카드 C-40을 그대로 따른다

## 1. 개요

플레잉카드 52장과 조커 1장으로 한다. 같은 숫자 두 장은 짝으로 내려놓을 수 있고, 조커는 짝이 없다. 차례마다 다음 사람의 패(뒷면)에서 한 장을 뽑아 짝이 맞으면 내려놓는다. 패를 먼저 다 내려놓은 사람은 빠지고, **마지막까지 조커를 든 1명이 당첨(도둑)** 이다.

| 항목 | v1 결정 |
| --- | --- |
| 인원 | 2~6명 (봇 포함) + 관전. 기본 4명 |
| 카드 | 플레잉카드 52장 + 조커 1장 = 53장. 짝은 **숫자(A~K)가 같으면** 무늬와 상관없이 맺는다 |
| 당첨 | **조커를 마지막까지 든 1명** (2026-11-28 결정) |
| 뽑는 방법 | 내 차례에 **다음 사람**(좌석 번호 순으로 바로 다음, 패가 남은 사람)의 패 뒷면에서 한 장을 고른다 |
| 첫 차례 | 무작위 |
| 턴 제한 시간 | 15초 (방 옵션) |
| 시간 초과 | 서버가 무작위 한 장을 대신 뽑는다. 2번 연속이면 봇이 대신 진행 (TF-12) |
| 게임 중 퇴장 | 봇이 이어서 한다. 다른 사람에게 알린다 (공통) |
| 목표 플레이 시간 | 2~4분 |
| 베팅 / 재화 | 없음 |

## 2. 규칙

| ID | 규칙 | 상세 |
| --- | --- | --- |
| TF-01 | 카드 | 52장(무늬 4 × 숫자 A~K 13)과 조커 1장. 서버가 `crypto.randomInt`로 섞는다 (원칙 5) |
| TF-02 | 나누기 | 첫 차례 자리부터 시계 방향으로 한 장씩 53장을 모두 나눈다. 인원에 따라 1~2장 차이가 날 수 있다 |
| TF-03 | 첫 짝 내기 | 시작할 때 **모든 사람의 패에서 짝을 서버가 자동으로** 내려놓는다. 같은 숫자가 3장이면 한 짝만 내고 1장이 남고, 4장이면 두 짝을 낸다. 내려놓은 짝은 **모두에게 공개**된다 (어떤 숫자 짝인지 보인다) |
| TF-04 | 차례 | 첫 차례는 무작위. 그다음은 좌석 번호 순(시계 방향)으로 패가 남은 사람만 돈다 |
| TF-05 | 뽑기 | 자기 차례에 **다음 사람**의 패(남에게는 뒷면만 보인다) 중 한 장의 위치를 골라 가져온다. 범위 밖이면 거부 (`INVALID_MOVE`, 상태 변화 없음). 가져온 카드가 무엇인지는 **뽑은 사람만** 안다 |
| TF-06 | 위치 섞기 | 카드가 한 장 빠지거나 들어오면 **서버가 그 사람의 패 순서를 무작위로 섞는다**. 그래서 위치만으로는 조커를 알 수 없다. 내 화면에서 패를 숫자 순으로 정렬해 보는 것은 보기일 뿐이고, 뽑기에는 영향이 없다 |
| TF-07 | 짝 내기 | 뽑은 카드가 내 패의 어떤 카드와 숫자가 같으면 **두 장을 자동으로** 내려놓는다 (공개). 아니면 패에 더한다. 조커는 짝이 없다 |
| TF-08 | 빠지기 | 패가 0장이 되면 그 사람은 빠진다(안전). 뽑는 사람이 짝을 내고 0장이 되거나, **뽑힌 사람이 마지막 카드를 빼앗겨** 0장이 되어도 빠진다. 빠진 사람은 이후 차례와 뽑기 대상에서 빠지고 관전 상태가 된다 |
| TF-09 | 다음 차례 | 뽑기가 끝나면 좌석 번호 순으로 **뽑은 사람의 다음 사람 중 패가 남은 사람**이 차례다 |
| TF-10 | 끝 | 패가 남은 사람이 **1명**만 남으면 끝난다. 그 사람은 항상 조커 한 장만 들고 있고, 그 사람이 당첨이다 (판의 홀짝 때문에 조커는 반드시 마지막에 남는다) |
| TF-11 | 결과 | 당첨 1명 = 2위, 나머지 = 1위 (파티 게임 공통). 모든 패와 내려놓은 짝은 끝난 뒤 공개한다 |
| TF-12 | 시간 초과 | 마감까지 못 뽑으면 서버가 **범위 안에서 무작위 위치**를 대신 뽑는다 (`isAuto = true`). 2번 연속이면 봇이 대신 진행하고(`autopilot`), 사람이 직접 뽑으면 돌려받는다 |
| TF-13 | 봇 | 자기 패와 **공개된 정보**(내려놓은 짝, 각자 패 수)만 쓴다. 위치가 섞이므로 알 수 있는 것이 없어 **무작위 위치를 뽑는다**. 1~2초 지연 후 행동한다 |
| TF-14 | 두 명 | 2명이 남으면 서로의 패에서 번갈아 뽑는다 (규칙은 같다). 처음부터 2명으로 시작해도 같다 |

### 예시 (4명, 12장 이하로 줄인 중간 상태)

| 순서 | 상황 | 결과 |
| --- | --- | --- |
| 1 | A 차례, 다음 사람 B의 패 3장 중 가운데를 뽑음. A의 패에 ♠7이 있고 뽑은 것도 7 | 7 두 장을 내려놓음. A 패 1장 감소 |
| 2 | B는 2장으로 줄어 위치가 섞임. 차례는 B | B가 C의 패에서 뽑음 |
| 3 | C의 마지막 카드를 B가 가져가 C 패가 0장 | C는 빠짐(안전). 다음 차례는 C를 건너뛰고 D |
| 4 | 마지막에 A와 D만 남음. A: 조커 1장 | D가 A의 패(1장)에서 뽑으면 D가 조커를 받음. D에게 짝이 없어 D 패에 조커만 남고 A는 0장이 되어 빠짐. 패가 남은 사람은 D 1명 → D 당첨 |

## 4. 진행 (상태 머신)

```
WAITING → STARTING → PLAYING ⟲(뽑기) → GAME_OVER → (리매치) → WAITING
```

| 상태 | 하는 일 | 다음 조건 |
| --- | --- | --- |
| WAITING | 입장, 준비, 옵션 | 방장이 시작 → STARTING |
| STARTING | 3초 카운트다운, 좌석 확정 | 끝 → PLAYING |
| PLAYING | 섞기, 나누기, 첫 짝 내기(TF-01~03), 차례마다 뽑기(TF-04~09) | 패가 남은 사람 1명 → GAME_OVER |
| GAME_OVER | 순위 확정, 기록 저장 | 리매치 → WAITING |

- 시작할 때 첫 짝 내기를 한 뒤 **패가 0장이 된 사람은 처음부터 빠진 상태**다(안전). 시작 직후에 이미 패가 남은 사람이 1명뿐일 수 있다. 이때는 그 사람이 바로 당첨이고, 뽑기 없이 끝난다 (인원이 적을 때만 일어난다).

## 5. 메시지 (공통과 다른 것)

### 클라이언트 → 서버

| 이벤트 | 페이로드 | 허용 상태 | 거부 조건 |
| --- | --- | --- | --- |
| `draw` | index: 0 ~ (다음 사람 패 수 − 1), turnId | PLAYING | 내 차례 아님 (`NOT_YOUR_TURN`), 만료된 turnId (`STALE_TURN`), 범위 밖 (`INVALID_MOVE`) |

### 서버 → 클라이언트

| 이벤트 | 대상 | 내용 |
| --- | --- | --- |
| `your_hand` | 본인만 | 내 패(카드 번호 배열). 시작할 때, 뽑거나 뽑힐 때마다 다시 보낸다 (복귀 때도, 원칙 4) |
| `turn_start` | 전체 | playerId(뽑는 사람), targetId(뽑힐 사람), turnId, 마감 시각 |
| `drawn` | 전체 | fromId, toId, 짝이 맞았다면 그 숫자(`matched`, 아니면 null), 뽑은 사람과 뽑힌 사람이 빠졌는지, isAuto, isBot. **뽑은 카드가 무엇인지는 짝이 맞았을 때의 숫자만 공개** |
| `player_out` | 전체 | playerId, 빠진 순서 |
| `player_replaced` | 전체 | (공통) |
| `game_over` | 전체 | 당첨자 playerId, 모든 사람의 마지막 패 |
| `error` | 요청자 | 에러 코드, 메시지 |

- 공유 상태(schema): 플레이어별 패 수(`handCount`), 빠졌는지, 빠진 순서, 내려놓은 짝 목록(숫자만, 공개), 현재 뽑는 사람과 대상, `turnId`, 마감. **패의 카드 번호는 넣지 않는다.**

## 6. 시간, 퇴장, 재접속, 봇

공통 엔진을 따른다. 도둑잡기에서 다른 점:

- **한 차례에 마감 하나**(TF-12). 뽑으면 마감 타이머를 취소한다.
- 시간 초과는 연속 횟수를 센다. 직접 뽑으면 0으로 돌아간다.
- 복귀하면 `your_hand`와 현재 `turn_start`를 다시 받는다.
- 게임 중 나간 자리는 봇이 이어서 뽑는다(공통). 나간 사람의 **패는 그대로** 이어받는다.

## 7. 화면

(시안은 별도로 확인받는다. 아래는 규칙에서 나오는 요구)

- 위: 참가자 칩(닉네임, 남은 패 수, 차례 표시). 빠진 사람은 "안전" 표시.
- 가운데: 지금 **뽑힐 사람**의 패를 뒷면으로 가로로 펼친다. 내 차례에 카드를 눌러 고른 뒤 **"뽑기"** 로 확정한다 (실수 방지).
- 아래: 내 패를 앞면으로 펼친다(숫자 순 정렬은 보기일 뿐). 내려놓은 짝은 위쪽에 모아 보여 준다.
- 짝이 맞으면 두 장이 내려가는 짧은 표시, 안 맞으면 내 패에 들어오는 표시. 뽑힌 카드의 정체는 뽑은 사람 화면에만 보인다.
- 결과: 본인이면 "당첨!"(조커를 들고 있음), 아니면 "통과!", 관전자는 "○○ 님 당첨". 모든 패 공개.
- 360px에서 패 8장 이상이 겹쳐도 고를 수 있어야 한다. 키보드: ←→로 카드 이동, Enter로 선택, Space로 뽑기. 움직임 줄이기 설정이면 애니메이션 생략.

## 9. 기록 (DB)

판 요약(ADR 0002, `games.summary`): 인원, 뽑기 횟수(`moveCount`), 대신 뽑은 횟수(`autoMoveCount`), 첫 짝 내기에서 이미 정해졌는지(`forced`), 봇 여부, 사람별 빠진 순서. 순위는 파티 게임 공통(당첨 2위, 나머지 1위). `/stats` 게임별 지표: 평균 뽑기 수, 시간 초과로 대신 뽑은 비율.
