# ADR 0001: Phase 1 구현 결정

- 상태: 제안 (리뷰 필요)
- 날짜: 2026-11-22

명세(v0.1)가 정하지 않았거나 구현 방식이 둘 이상인 부분에서 내린 결정이다. 명세와 충돌하는 결정은 없고, 명세를 보완한 부분은 `docs/specs/liars-dice.md` 6장과 9장에 반영했다.

## 서버 구조

- **게임 진행과 전송 분리.** `LiarsDiceMatch`(상태 머신)는 Colyseus를 모르고 `MatchIO`로만 메시지를 낸다. `LiarsDiceRoom`은 연결·세션·빈도 제한만 다룬다. 그래서 가상 시간 스케줄러로 1,000판을 1초 안에 돌린다.
- **타이머.** Colyseus `room.clock`(16ms 틱)을 쓰지 않고 방마다 단발 `setTimeout`을 모아 둔 `TimerScheduler`를 쓴다 (원칙 7). dispose 시 전부 해제한다.
- **공개 playerId.** 공유 상태의 `playerId`는 서버가 발급한 무작위 ID다. 브라우저 게스트 ID를 공개하면 다른 사람이 그 ID로 접속해 자리를 빼앗을 수 있다(E-13 동작 악용).
- **room_state.** 명세의 `room_state`는 Colyseus 공유 상태 동기화로 구현했다 (재접속 시 전체 상태 자동 전송).
- **빈도 제한.** 초당 10회 초과는 무시하고 `RATE_LIMITED`를 한 번 알린다. 10초 안에 세 번 위반하면 4002로 연결을 끊는다. Colyseus 자체 상한(초당 40)은 안전망이다.
- **봇 지연 vs 턴 제한.** 봇 지연(1~3초)은 턴 제한보다 짧게 자른다.
- **랜덤 매칭.** 공개 방이고 대기실이며 빈자리가 있을 때만 매칭 목록에 노출한다. 방 코드로는 언제든 들어올 수 있다(관전 포함).

## 명세를 보완한 부분 (확인 필요)

1. **방장 준비.** 방장은 "시작"을 누르는 것으로 준비한 것으로 본다. 나머지 사람만 준비해야 시작할 수 있다.
2. **빈자리 채우기.** 켜져 있으면 시작할 때 최대 인원까지 봇을 채운다. 기본값(6명, 켜기)이면 혼자 시작해도 6인 판이 된다.
3. **추가 메시지.** 대기실 UI(명세 8장)에 필요한 `set_options`, `add_bot`, `remove_bot`(클라이언트→서버)과 입장 직후의 `welcome`(서버→본인)을 추가했다.
4. **추가 에러 코드.** `start_game` 거부 조건 등을 코드로 옮겼다: `NOT_HOST`, `NOT_ENOUGH_PLAYERS`, `NOT_ALL_READY`, `INVALID_STATE`, `INVALID_OPTIONS`, `INVALID_NICKNAME`, `INVALID_MESSAGE`, `SERVER_DRAINING`.
5. **S-07 대리 플레이.** 대리 중 봇의 선언은 `isAuto=true`, 처음부터 봇인 플레이어의 선언은 `isAuto=false`로 기록한다.
6. **E-10 범위.** "사람"은 좌석에 앉은 사람(탈락 후 관전 포함)만 센다. 처음부터 관전자만 남으면 방을 닫는다.
7. **S-10 미결정.** `ALONE_WITH_BOTS_POLICY=continue`(기본) / `end`로 설정에 빼 두었다.
8. **리매치.** 결과 화면의 누구나 리매치할 수 있다. 나간 사람과 그 자리를 이어받은 봇은 빠지고, 관전자는 빈자리에 들어간다.

## 배포 접속 경로

- **결정:** GitHub Actions는 Tailscale(tag:ci)로 tailnet에 잠시 들어와 VM(tag:server)의 SSH에 접속한다. VM의 22번은 인터넷에 열지 않는다 (phase1 "80/443만 개방"과 일치).
- **검토한 대안:** 공개 SSH(키 전용)는 설정이 없지만 SSH가 상시 스캔 대상이 되고 러너 IP를 제한할 수 없다. VM이 새 이미지를 당겨오는 방식은 들어오는 접속이 없지만 배포 시점과 실패를 GitHub에서 보기 어렵다.
- **대가:** Tailscale 서비스에 의존한다. Tailscale이 멈추면 배포만 실패하고 서비스 중인 게임에는 영향이 없다.

## 남은 위험

- **배포 중 판 유지.** 지금은 종료 신호를 받으면 새 방을 막고 진행 중인 판이 끝날 때까지(최대 15분) 기다린다. 그동안 새 방을 만들 수 없다. 새 방 공백까지 없애려면 블루/그린(두 서버 컨테이너 + Caddy 전환)이 필요하다.
- **게스트 신원.** 게스트 ID는 브라우저 저장값이라 기기를 바꾸면 이어지지 않는다 (로그인 방식 미결정).
- **E2E 시간 배율.** E2E는 `GAME_TIMING_SCALE=0.05`로 돈다. 실제 시간(턴 30초, 봇 1~3초)의 판 길이는 M6 부하 테스트에서 따로 잰다.
